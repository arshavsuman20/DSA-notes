# 1. Two Sum

## Problem Statement-
Given an array of integers `nums` and an integer `target,`return the indices `i` and `j` such that `nums[i] + nums[j] == target` and `i != j`. Return answer with smaller index first.

## Understanding the Problem Statement-
We have been given an array `nums` and a `target` value. We have to return pair of indices whose value’s sum will be equal to `target` but it should not be the same index. We also have to return the lower index first followed by the next index. The question itself states that only one valid answer exists.

## 1.Brute Force Approach-
The most basic and least efficient way to solve this problem is to check every pair of different elements in array and return the first pair that sums up to the target.

### Algorithm:
1. Iterate through array with two nested loops to check every pair of different elements.  
2. If sum of pair equals target, return indices of pair.  
3. If no such pair is found, return empy array.

### Working with Test Cases:
**Test Case1:**  
Input: `nums[]=[2,7,11,15]`, `target=9`  
Output: `[0,1]`  
Explanation:  
According to the algorithm, we iterate over the array with nested loops. The first pair of indices sum equals the target and we return the pair of indices as answer.  
**Test Case2:**  
Input: `nums[]=[4,5,6]`, `target=10`  
Output: `[0,2]`  
Explanation:  
Here when the loop goes through first pair, it returns sum of `9` which is not equal to `target`, and the next pair gives a sum of `11` which is again not equal to `target`. But first and last indexes give a sum of `10` which is equal to `target`. So those pair of indices are returned as answer.

### Solution:
```java  
public class Solution {  
    public int[] twoSum(int[] nums, int target) {  
        for (int i = 0; i < nums.length; i++) {  
            for (int j = i + 1; j < nums.length; j++) {  
                if (nums[i] + nums[j] == target) {  
                    return new int[]{i, j};  
                }  
            }  
        }  
        return new int[0];  
    }  
}  
```  
Now since two loops are nested here, so Time Complexity = `O(n2)` and Space Complexity = `O(1)`.

## 2.Hash Map Approach-
We use a hash map to store value and index of each element in array. Then, we can iterate through the array and check if the complement of the current element exists in the hash map. The complement must be at a different index, because we can't use the same element twice.

### Algorithm:
1. Create a hash map to store value and index of each element in array.  
2. Iterate through each and compute complement of current element, that is `target - nums[i]`.  
3. Check if complement exists in the hash map.  
4. If yes, then return indices of current element and its complement.  
5. If no, then return empty array.

### Working with Test Cases:
**Test Case1:**  
Input: `nums[]=[2,7,11,15]`, `target=9`  
Output: `[0,1]`  
Explanation:  
We go through entire array and store every value with its index.
| i | nums[i] | Hashmap |
| :---- | :---- | :---- |
| 0 | 2 | {2 → 0} |
| 1 | 7 | {2→0, 7→1} |
| 2 | 11 | {2→0, 7→1, 11→2} |
| 3 | 15 | {2→0, 7→1, 11→2, 15→3} |

So, after first iteration, Hashmap becomes:  
`{  
    2 : 0,  
    7 : 1,  
    11 : 2,  
    15 : 3  
}`
Now we again go through array and check if `complement = target - nums[i]` exist in hashmap.  
`nums[0]=2`  
`diff=target-nums[0]=9-2=7`  
`7` exists in HashMap → Yes  
`map.get(7)=1`  
Return `[0,1]`

### Solution:
```java  
public class Solution {  
    public int[] twoSum(int[] nums, int target) {  
        Map<Integer, Integer> indices = new HashMap<>();  // val -> index
        for (int i = 0; i < nums.length; i++) {  
            indices.put(nums[i], i);  
        }
        for (int i = 0; i < nums.length; i++) {  
            int diff = target - nums[i];  
            if (indices.containsKey(diff) && indices.get(diff) != i) {  
                return new int[]{i, indices.get(diff)};  
            }  
        }
        return new int[0];  
    }  
}  
```  
Now, by using HashMap we achieve Time Complexity of `O(n)` and Space Complexity of `O(n)`.
