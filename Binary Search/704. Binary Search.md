# 704. Binary Search

## Problem Statement-

Given an array of integers `nums` which is sorted in ascending order, and an integer `target`, write a function to search `target` in `nums`. If `target` exists, then return its index. Otherwise, return -1.

## Understanding Problem Statement-

We are given an integer array of `nums` and a `target`. We have to search the `target` in the array `nums`. If the `target` exists in the array, we return the index where `target` is found. Otherwise we have to return -1.

## 1. Iterative Binary Search Approach-

The array `nums` is sorted.  
Instead of linear searching, we:

    * Look at middle element.  
    * Decide whether target lies on **left half** or **right half**.  
    * Discard half of array each time.

The idea of “divided by 2” makes binary search fast.

### Algorithm:

1. Initialize:  
    * `low = 0`  
    * `high = n-1`  
2. While `low<=high`:  
    * Compute `mid = low + (right - left)/2`  
    * If `nums[mid] == target` -> return `mid`  
    * If `target > nums[mid]`, we search the right half -> `low = mid+1`.  
    * Else, search for left half -> `high = mid-1`.  
3. If loop ends, target does not exists -> return `-1`.

### Working with Test Cases:

Input: `nums = [-1,0,3,5,9,12]`, `target = 9`  
Output: `4`  
Explanation:

| iteration | low | high | mid | nums[mid] | Comparison | Action |
| :---- | :---- | :---- | :---- | :---- | :---- | :---- |
| 1 | 0 | 5 | 2 | 3 | 9 > 3 | low = mid+1 -> 3 |
| 2 | 3 | 5 | 4 | 9 | 9 == 9 | return 4 |

We, initialize `low = 0` and `high = n-1`. For calculating the value of `mid`: we do not use `(low + high)/2`. Instead, we use `low + (high - low)/2`, because the latter does not gives time limit exceeded for higher integer values.  
So, the working goes like: we pick the middle element and if target is found we return index. If target is greater than `nums[mid]`, increase low by `mid + 1`, which means target is on right side. Otherwise, we decrease high by `mid - 1`, which means target is on left side.

### Solution:

```java  
class Solution {  
    public int search(int[] nums, int target) {  
        int n=nums.length; int low=0,high=n-1;  
        while(low<=high){  
            int mid = (low+high) / 2;   
            if(nums[mid]==target)   return mid;  
            else if(target>nums[mid])   low=mid+1;  
            else    high=mid-1;  
        }     
        return -1;  
    }  
}  
```  
Now, each iteration cuts search space in half. Maximum steps is `log(n)`. So overall Time Complexity is `O(logn)`.  
No extra data structures are used and only variables, so Overall Space Complexity is `O(1)`.

## 2. Recursive Binary Search-

The array is sorted.  
At every step, we:

    * Check the **middle element**.  
    * Decide whether the target lies in the **left half** or **right half.**

Instead of looping, we let recursion do the repetition.  
Each recursive call reduces search space by half.

### Algorithm:

1. Start with `low = 0`, `high = n-1`.  
2. If `low > high`, target does not exists -> return -1.  
3. Find `mid = (low)+ (high-low)/2`.  
4. If `nums[mid] == target` -> return `mid`.  
5. If `target > nums[mid]` -> search right half.  
6. Else -> search left half.

### Working with Test Cases:

Input: `nums = [-1,0,3,5,9,12]`, `target = 9`  
Output: `4`  
Explanation:  
Call 1:   
`binarysearch(nums, low=0, high=5)`  
`mid = (0+5)/2 = 2`  
`nums[mid] = 3`  
`9 > 3` -> search right half. `binarysearch(nums, 3, 5)`.  
Call 2:  
`low = 3, high = 5`  
`mid = (3+5)/2 = 4`  
`nums[mid] = 9`  
Found target, so return `4`. Call stack unwinding. `return 4-> return 4-> return answer`.  
So, final output is `4`.

### Solution:

```java  
class Solution {  
    public int search(int[] nums, int target) {  
        return binarysearch(nums, 0, nums.length - 1, target);  
    }  
    int binarysearch(int[] nums, int low, int high, int target) {  
        if (low > high) return -1;  
        int mid = (low + high) / 2;  
        if (nums[mid] == target) return mid;  
        else if (target > nums[mid])  
            return binarysearch(nums, mid + 1, high, target);  
        else  
            return binarysearch(nums, low, mid - 1, target);  
    }  
}  
```  
Each recursive call halves the array, Maximum depth is `log(n)`. So overall Time complexity is `O(logn)`.  
Recursive calls go on the call stack. Maximum stack depth = `log₂(n).`  
So, overall Space complexity is `O(logn)` due to recursion.

## 3. Upper Bound Approach-

Upper bound binary search finds the **first index where a value greater than the target appears**.  
Once we know that position, the actual target—if it exists—must be right before it.  
So instead of directly searching for the target, we search for the boundary where values stop being ≤ target.  
Then we simply check whether the element just before that boundary is the target.

### Algorithm:

1. Set `l=0` and `r=len(nums)`.  
2. While `l<r`:  
    * Compute midpoint `m`.  
    * If `nums[m] > target`, shrink the right side: `r=m`.  
    * Otherwise (`nums[m] <= target`), shrink the left side: `l=m+1`.  
3. After the loop:  
    * `l` is the upper bound: first index where `nums[l] > target`.  
    * So the potential location of the target is `l-1`.  
4. If `l>0` and `nums[l-1] == target`, return `l-1`.  
5. Otherwise, return `-1`.

### Working with Test cases:

Input: `nums = [-1,0,3,5,9,12]`, `target = 9`  
Output: 4  
Explanation:  
Iteration 1:  
`l = 0, r = 6`  
`m = 0 + (6 - 0)/2 = 3`  
`nums[m] = nums[3] = 5`  
Comparison: `nums[m] > target ? 5 > 9` which means no.  
Else case: `l = m + 1 = 4`.  
Iteration 2:  
`l = 4, r = 6`  
`m = 4 + (6 - 4)/2 = 5`  
`nums[m] = nums[5] = 12`  
Comparison: `nums[m] > target ? 12 > 9` which means yes.  
`r = m = 5`.  
Iteration 3:  
`l = 4, r = 5`  
`m = 4 + (5 - 4)/2 = 4`  
`nums[m] = nums[4] = 9`  
Comparison: `nums[m] > target ? 9 > 9` which means no.  
Else: `l = m + 1 = 5`.  
Loop ends: `l=5`, `r=5` and `l<r`: so exit loop.  
Now perform the final check: `return (l > 0 && nums[l - 1] == target) ? l - 1 : -1;`  
Condition is true so we return `4`.  
So, final output is `4`.

### Solution:

```java  
public class Solution {  
    public int search(int[] nums, int target) {  
        int l = 0, r = nums.length;

        while (l < r) {  
            int m = l + ((r - l) / 2);  
            if (nums[m] > target) {  
                r = m;  
            } else {  
                l = m + 1;  
            }  
        }  
        return (l > 0 && nums[l - 1] == target) ? l - 1 : -1;  
    }  
}  
```  
So, this is similar to iterative binary search approach: overall Time Complexity is `O(logn)` and overall Space Complexity is `O(1)`.

## 4. Lower Bound Approach-

Lower Bound binary search finds the **first index where a value is greater than or equal to target**.  
This means if the target exists in the array, this lower-bound index will point exactly to its first occurence.  
So, instead of directly searching for equality, we search for the **leftmost position** where the target could appear, then verify it.  
This approach is especially useful for sorted arrays because it avoids overshooting and naturally handles duplicates.

### Algorithm:

1. Initialize:  
    * `l=0`.  
    * `r = len(nums)`  
2. While `l<r`:  
    * Compute midpoint `m`.  
    * If `nums[m] >= target`, shrink the search to the left half: `r=m`.  
    * Otherwise (`nums[m]<target`), search in the right half: `l=m+1`.  
3. After the loop:  
    * `l` is lower bound: first index where value >= target.  
4. If `l` is within bounds and `nums[l] == target`, return `l`.  
5. Otherwise, return `-1`.

### Working with Test Cases:

Input: `nums = [-1,0,3,5,9,12]`, `target = 9`  
Output: 4  
Explanation:  
Iteration 1:  
`l = 0, r = 6`  
`m = 0 + (6 - 0)/2 = 3`  
`nums[m] = nums[3] = 5`  
Comparison: `nums[m] >= target ? 5 >= 9` which means no.  
Else case: `l = m + 1 = 4`.  
Iteration 2:  
`l = 4, r = 6`  
`m = 4 + (6 - 4)/2 = 5`  
`nums[m] = nums[5] = 12`  
Comparison: `nums[m] >= target ? 12 >= 9` which means yes.  
`r = m = 5`.  
Iteration 3:  
`l = 4, r = 5`  
`m = 4 + (5 - 4)/2 = 4`  
`nums[m] = nums[4] = 9`  
Comparison: `nums[m] >= target ? 9 >= 9` which means yes.  
`r = m = 4`.  
Loop ends: `l=4`, `r=4` and `l<r`: so exit loop.  
Now perform the final check: `return (l < nums.length && nums[l] == target) ? l : -1;`  
Condition is true so we return `4`.  
So, final output is `4`.

### Solution:

```java  
public class Solution {  
    public int search(int[] nums, int target) {  
        int l = 0, r = nums.length;

        while (l < r) {  
            int m = l + (r - l) / 2;  
            if (nums[m] >= target) {  
                r = m;  
            } else {  
                l = m + 1;  
            }  
        }  
        return (l < nums.length && nums[l] == target) ? l : -1;  
    }  
}  
```  
So, this has a same complexity as the Upper Bound one.
