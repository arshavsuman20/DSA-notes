# 739. Daily Temperatures

## Problem Statement-

Given an array of integers `temperatures` represents the daily temperatures, return an array `answer` such that `answer[i]` is the number of days we have to wait after the `ith` day to get a warmer temperature. If there is no future day for which this is possible, keep `answer[i] == 0` instead.

## Understanding the Problem Statement-

Here, we have to return warmer day temperature or future. The concept used here is similar to Previous Greater Element (used in Monotonic Stack), where `arr[i]`’s element is immediately greater and is on left.

## 1. Brute Force Approach-

For each day, we simply look forward to find the next day with a higher temperature.  
We compare the current day with every future day until we either find a warmer one or reach the end.  
If we find a warmer day, we record how many days it took.  
If not, the answer is `0`.  
This method is easy to understand but slow because every day may scan many days ahead.

### Algorithm:

1. Let `res` store the number of days until a warmer temperature.  
2. For each index `i`:  
    * Start checking from the next day `j = i+1` and count how many steps it takes to find a warmer day.
    * If a warmer day is found, store count.
    * Otherwise,  store `0`.
3. Return result array.

### Working with Test Cases:

Input: `temperatures = [30,38,30,36,35,40,28]`

Output: `[1,4,1,2,1,0,0]`

Explanation:

`i=0: temperature = 30` here, 

`j=1`, 38>30 so break, count=1: `res[0]=1`.

`i=1: temperature = 38` here, 

	`j=2`: 30<=38 so count=2,

	`j=3`: 36<=38 so count=3,

	`j=4`: 35<=38 so count=4,

	`j=5`: 40>38 so break,

`res[1] = 4`.

`i=2: temperature = 30` here,

	`j=3`: 36>30 so break, 

	`res[2]=1`.

`i=3: temperature = 36` here,

	`j=4`: 35<=36 so count =2,

	`j=5`: 40>36 so break,

	`res[3]=2`.

`i=4: temperature = 35` here,

	`j=5`: 40>35 so break,

	`res[4]=1`.

`i=5: temperature = 40` here,

	`j=6`: 28<=40 so count=2,

	`j=7`: out of bounds, no warmer day:- `res[5]=0`

`i=6`: `temperature = 28` here,

	`j=7`: out of bounds, no warmer day:- `res[6]=0`

So, final output is: `res = [1, 4, 1, 2, 1, 0, 0]`.

### Solution:

```java  
public class Solution {  
    public int[] dailyTemperatures(int[] temperatures) {  
        int n = temperatures.length;  
        int[] res = new int[n];

        for (int i = 0; i < n; i++) {  
            int count = 1;  
            int j = i + 1;  
            while (j < n) {  
                if (temperatures[j] > temperatures[i]) {  
                    break;  
                }  
                j++;  
                count++;  
            }  
            count = (j == n) ? 0 : count;  
            res[i] = count;  
        }  
        return res;  
    }  
}  
```

Here, Time complexity is `O(n^2)` and Space complexity is:

`O(1)` for extra space, and `O(n)` for output array.

## 2. Stacks Approach-

Brute force would check future days which takes `O(n²)`.

Instead, we use a monotonic decreasing stack:

* Stack stores temperatures that haven’t found a warmer future day yet.  
* Stack is decreasing by temperature.  
* When a warmer temperature appears, it resolves answers for stack elements.

### Algorithm:

1. Create an array `res[]` initialized with `0`.  
2. Use a stack storing `{temperature, index}`  
3. Traverse temperatures from left to right.  
4. For each day `i`:  
    * While stack is not empty and `currentTemp > stackTop.temperature:`  
        * Pop stack  
        * Answer for that popped index = `i - oldIndex`  
    * Push `{currentTemp, i}` into stack.  
5. Remaining stack elements, so no warmer day, so answer stays `0`

### Working with Test Cases:

Input: `temperatures = [30,38,30,36,35,40,28]`

Output: `[1,4,1,2,1,0,0]`

Explanation:

`temperatures = [30, 38, 30, 36, 35, 40, 28]`

| Day(i) | Temp | Stack | Action | Result Array |
| :---- | :---- | :---- | :---- | :---- |
| 0 | 30 | [] | push (30,0) | [0,0,0,0,0,0,0] |
| 1 | 38 | (30, 0) | pop → res[0]=1 | [1,0,0,0,0,0,0] |
|  |  | [] | push (38,1) |  |
| 2 | 30 | (38,1) | push (30,2) | [1,0,0,0,0,0,0] |
| 3 | 36 | (38,1),(30,2) | pop → res[2]=1 | [1,0,1,0,0,0,0] |
|  |  | (38,1) | push (36,3) |  |
| 4 | 35 | (38,1),(36,3) | push (35,4) | [1,0,1,0,0,0,0] |
| 5 | 40 | (38,1),(36,3),(35,4) | pop → res[4]=1 |  |
|  |  | (38,1),(36,3) | pop → res[3]=2 |  |
|  |  | (38,1) | pop → res[1]=4 |  |
|  |  | [] | push (40,5) | [1,4,1,2,1,0,0] |
| 6 | 28 | (40,5) | push (28,6) | [1,4,1,2,1,0,0] |

So, Final Output is `[1, 4, 1, 2, 1, 0, 0]`.

### Solution:

```java  
public class Solution {  
    public int[] dailyTemperatures(int[] temperatures) {  
        //PGEE, previous greater element: a[st.peek()] < a[i];  
        int[] res = new int[temperatures.length];  
        Stack<int[]> st = new Stack<>(); //temperature, index  
        for (int i = 0; i < temperatures.length; i++) {  
            //int t = temperatures[i];  
            ///if current temp>tos of stack, top day's ans found  
            while (!st.isEmpty() && temperatures[i] > st.peek()[0]) {  
                int[] pair = st.pop();  
                res[pair[1]] = i - pair[1]; //pair[1]=old index  
            }  
            st.push(new int[]{temperatures[i], i}); //current day in stack  
        }  
        return res;  
    }  
}  
```  
Here, each element is pushed once and popped once, so Total operations are `2n.` Time complexity is `O(n)`.  
Stack can hold atmost `n` elements, and result array is of size `n`.  
So, space complexity is `O(n)`.
